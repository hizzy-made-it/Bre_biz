# Wander & Revel Event Services — live site

Scope (Nov 15 2026, owner-approved): the public website is open to everyone (no access code). A separate owner admin at `/admin` edits all site text, photos, services and pricing, food and bar menus with prices and photos, the gallery and journal, inquiries, event plans, a client spreadsheet, and payments. Booked clients sign in at `/portal` with their email and an admin-issued access code to see their schedule, guest count, menu selections, updates and balance, and can pay by card through Stripe Checkout. The business name and supplied logo are the confirmed brand identity. Do not invent business credentials, pricing, clients or completed events; prices are entered by the owner.

Stack: Next.js 16 standalone on Node.js 24, Railway Dockerfile, better-sqlite3 using one persistent SQLite volume at `/data`. All site data is one shared JSON row (`demo_states.user_id = 'site'`) with version CAS; writes go through `changeSite()` in `lib/site-store.ts` inside an immediate transaction. Uploaded photos live in `/data/uploads` and are served from `/api/media/<uuid>.<ext>` after magic-byte checks. Railway runs one replica with a health check at `/api/health`. Do not scale multiple app replicas against SQLite.

Environment (runtime only, never commit): `ADMIN_PASSWORD` (8+ chars), `SESSION_SECRET` (32+ chars; `DEMO_SESSION_SECRET` is accepted as a fallback), `APP_ORIGIN` (comma-separated exact https origins, e.g. the custom domain and www; the Railway domain is added automatically), optional `STRIPE_SECRET_KEY` and `STRIPE_WEBHOOK_SECRET` (webhook URL `/api/stripe/webhook`, events `checkout.session.*`). Mutations require an allowed Origin. Never accept OAI identity headers. Sessions are signed HttpOnly SameSite=Lax cookies; changing `ADMIN_PASSWORD` signs out admins and resetting a client's code signs out that client.

Data rules: the public `/api/site` response must never include inquiries, events, clients or payments. Client portal responses must never include internal notes or the access code. Saved food choices belong to each event and keep their own details when catalog dishes change; older saved sites gain missing fields without resetting content. Changes to a linked event's date, guests, venue, schedule, food or drinks are logged to the client's update feed.

UI: approved palette ivory #F7F3EA, oat #DDD4C5, sage #8C947E, olive #555C3D, champagne #B6A184, charcoal #292A27. Light default, saved dark preference supported. Tagline: A Place for Every Story. Main navigation: Home, About us, Services, Menus, Gallery, Inquire, plus Client login. Public copy defaults live in `lib/site-defaults.ts` and are editable from the admin; public layout in `app/brand.css`. Respect reduced motion, keyboard navigation, validation, saving and error states.

Verification: `npm run build`, `npx tsc --noEmit --pretty false`, and `npm run verify:demo` (loopback-only, temporary data and credentials, two-minute deadline, synthetic data). Keep `.openai/hosting.json` identity metadata, but do not use Sites publishing for this Railway deployment.
